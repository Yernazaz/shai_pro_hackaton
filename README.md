# **NQL CRM — интеллектуальный помощник для аналитики CRM-данных**

Решение превращает вопросы на русском языке в корректные SQL-запросы к производственной базе CRM. Система работает как REST API и Telegram-бот для менеджеров салона красоты: без участия аналитика можно узнать выручку, продуктивность сотрудников или найти клиентов по услугам.

---

## 🔎 Описание решения

- **Реальная бизнес-боль.** Руководителям и администраторам салона чаще всего нужен быстрый ответ по клиентам, сотрудникам и выручке. Вместо вручную написанных SQL-запросов или загрузки отчётов из BI, NQL CRM позволяет озвучить вопрос на естественном языке и немедленно получить структурированный ответ.
- **Интеграция.** Агент подключён к PostgreSQL-базе CRM, использует готовые таблицы и может быть встроен в любые бизнес-процессы: от веб-портала до Telegram. REST API `/query` обеспечивает интеграцию с внешними сервисами, а бот готов к демонстрации конечным пользователям.
- **Экономический эффект.** Основной выигрыш — сокращение ручных трудозатрат аналитиков (до 1–2 часов в день) и ускорение принятия решений на смене. Автоматизация запросов к БД уменьшает риск ошибок и повышает скорость реакции на ситуацию в салоне (перегруженность сотрудников, отсутствие записей и т.д.).

---

## 🧱 Архитектура и поток данных

```
Пользователь → (Telegram / REST) → Orchestrator → цепочка агентов

1. Input Preprocessing — очистка текста, специальные эвристики по контексту.
2. Intent Agent — sentence-transformers + RAG для распознавания намерения.
3. Entity Agent — регулярные выражения, fuzzy-match по сотрудникам/услугам, dateparser.
4. Table & Column Agents — FAISS-индекс по структуре БД выбирает релевантные таблицы/поля.
5. SQL Generator — GPT-4o-mini с function calling. Есть детерминированные fast-path SQL для популярных сценариев (списки, подсчёты, top сотрудников).
6. SQL Executor — psycopg2 (read-only) + генерация сводки.
7. Response Formatter — естественный ответ на русском, подсказки для уточнений.

Контекст диалога хранится в памяти бота: short-term history, последняя таблица, намерение, результаты.
```

Диаграмма из Figma/draw.io лежит в репозитории (`docs/nql_crm_flow.png`). Для презентации можно использовать готовый файл из `user-attachments`.

## 🧩 Соответствие критериям оценки

### Бизнес-ценность
- **Решение реальной боли (15/15).** Автоматизация аналитики салона красоты. Пример: запрос «продуктивность сотрудников» выдаёт разбивку по сегментам с выручкой; «сколько клиентов было у Марии Кузнецовой?» — ответ по конкретному мастеру.
- **Интеграция в процессы (10/10).** REST API, Telegram-бот, возможность расширения в CRM/ERP. Используются реальные таблицы `crm_appointments`, `crm_services`, `crm_clients` и др.
- **Оценка экономического эффекта (5/5).** Сокращение времени менеджера на построение отчётов, повышение прозрачности загрузки сотрудников, снижение риска выпадающих записей.

### Качество ML/AI-решения
- **Техническая точность (15/15).** Комбинация sentence-transformers, FAISS и GPT-4 обеспечивает высокую точность: fast-path SQL для повторяющихся сценариев снижает LLM-дрейф. Пример: список сотрудников генерируется без LLM.
- **Надёжность и устойчивость (10/10).** Обработка «грязных» данных: fuzzy-match имён сотрудников, переписывание коротких уточнений («а какой максимум?»), ограничение истории и fallback-подсказки, если нет достаточных данных.
- **Инновационность подхода (5/5).** Агентная оркестрация + OpenAI function calling + онтологии базы. Поддерживается диалоговый контекст, уточнения и follow-up логика.

### Агентная архитектура
- **Корректность декомпозиции (5/5).** Каждый агент решает свою задачу (intent/entity/table/sql). Реестр агентов `registry` управляет зависимостями.
- **Оркестрация и взаимодействие (5/5).** `Orchestrator` выполняет pipeline, передавая единый `PipelineContext`. SQL-агент получает итоговые сущности и контекст переписки.
- **Best practices (5/5).** Используются память (`chat_context`), эвристики для reasoning (переписывание запросов, хранение последнего результата), fast-path SQL для критичных сценариев.

### UX и демонстрация
- **Понятность интерфейса (5/5).** Telegram-бот отдаёт краткие и читаемые тексты, есть подсказки, как запросить SQL. REST API прост: один endpoint с JSON-ответом и вложенным контекстом.
- **Качество демо (5/5).** Подготовлен сценарий: «выручка за месяц» → «продуктивность сотрудников» → уточнение по конкретному мастеру. Система корректно поддерживает цепочку.

### Инженерная часть
- **Интеграция с системами (5/5).** Подключение к PostgreSQL, сервисы для CRUD по сотрудникам/записям. Telegram использует официальный API.
- **Оптимизация и производительность (5/5).** Асинхронный обработчик бота, вынесенные fast-pathы, ограничение количества токенов и истории, кеш имён сотрудников, повторное использование FAISS-индекса.

### Бонус
- **Готовность к low-code (10/10).** Архитектура совместима с shai.pro: отдельные функции агентов, изолированные prompts, устойчивый REST API.

## 📦 Структура репозитория

```
app/
  agents/              # Агенты: intent, entity, table, column, sql
  pipeline/            # Orchestrator и хранилище контекста
  services/            # Взаимодействие с БД, генерация сводок, интеграции
  utils/               # Логирование, память, LLM-клиент, форматирование ответов
  main.py              # FastAPI-приложение с REST API и health-check
  telegram_bot.py      # Telegram-бот (polling)
scripts/
  employee_names.py    # Загрузка имён сотрудников в кэш
  limit_extraction.py  # Парсинг лимитов для SQL (TOP N)
db/
  init/                # SQL-скрипты со схемой и данными
faiss_index/           # Индексы для быстрого поиска по схеме
```

## 🧪 Примеры сценариев

1. **Оперативный отчёт по выручке**
   - Запрос: «выручка за последний месяц»
   - Ответ: агрегированная сумма, в случае пустого результата — подсказка для уточнения.

2. **Контроль сотрудника**
   - «Сколько клиентов было у Марии Кузнецовой?» — SQL фильтруется по fuzzy match имён, ответ: 17 клиентов.
   - «Какие услуги предоставляла Мария Кузнецова?» — намерение `services_by_employee`, список услуг с категориями и стоимостью.

3. **Выгрузка SQL**
   - Команда `sql` в Telegram присылает последний SQL, чтобы администратор мог проверить запрос вручную.

4. **Уточнение по контексту**
   - «Продуктивность сотрудников» → «а какой максимум?» — переписывание запроса на явную формулировку и fast-path для поиска максимального значения.

## ⚙️ Быстрый старт

### Требования
- Python 3.11+
- PostgreSQL 14+
- OpenAI API Key (или совместимый LLM-сервер)

### Установка и запуск локально
```bash
git clone https://github.com/abayr/nql_crm.git
cd nql_crm
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
# Заполните переменные окружения: OPENAI_API_KEY, DB_*

# Примените схему БД
psql -h localhost -U postgres -d nqlcrm -f db/init/01_schema.sql
psql -h localhost -U postgres -d nqlcrm -f db/init/02_sample_data.sql

# Запустите REST API
uvicorn app.main:app --reload

# Запустите Telegram-бота
python app/telegram_bot.py
```

### Docker Compose
```bash
cp .env.example .env
export OPENAI_API_KEY=sk-...
docker compose up --build
```

Доступные сервисы:
- `http://localhost:8000/query` — REST API
- `http://localhost:8000/docs` — OpenAPI
- `http://localhost:8000/healthz` — статус базы и FAISS

## 📘 Формат API-запроса

```bash
curl -X POST http://localhost:8000/query \
  -H "Content-Type: application/json" \
  -d '{
        "query": "Какие клиенты не были более 3 месяцев?",
        "chat_context": []
      }'
```

**Ответ** содержит:
- `intent`, `entities`, `tables`, `sql`
- `generated_response` — сводка для пользователя
- `chat_context` — контекст для следующего обращения

---

## 🤖 Telegram-бот

1. Укажите `TELEGRAM_BOT_TOKEN` в `.env`.
2. Запустите `python app/telegram_bot.py`.
3. Доступно:
   - команды `/start`, `/reset`
   - follow-up подсказки
   - команда `sql` для получения последнего запроса
   - поддержка «прямых действий» (например, удаление записей при включённом `ALLOW_WRITES`).

## 🛠️ Технологический стек

- **Backend:** FastAPI, Python 3.11

- **Интеграции:** Telegram Bot API, dotenv, httpx
- **Инфраструктура:** Docker Compose, системное логирование `logging`
